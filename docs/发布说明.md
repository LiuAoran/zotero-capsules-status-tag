# 发布说明

仓库布局：静态插件文件在 `addon/`，源码在 `src/`，生成文件在 `build/`，发布产物在 `dist/`，直接下载的当前 XPI 在 `downloads/`。

## 1.0.1

修复启动时状态列排序标记与实际文献顺序不一致的问题。保留其他列排序，普通状态保存不增加额外排序。

## 构建当前版本

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run release
```

输出：

- `dist/zotero-capsules-status-1.0.1.xpi`
- `dist/zotero-capsules-status-1.0.1-source.zip`
- `dist/SHA256SUMS-1.0.1.txt`
- `downloads/zotero-capsules-status-1.0.1.xpi`
- `downloads/SHA256SUMS.txt`（只校验该目录中的 XPI）

打包脚本从 `addon/manifest.json` 读取版本。源码包使用明确的公开文件列表，排除 `.git`、开发依赖、缓存、构建目录和历史安装包；生产 XPI 不包含测试运行器。

## 更新与发布到 GitHub

1. 同步更新 `addon/manifest.json`、`package.json` 和 `package-lock.json` 的版本。
2. 更新中英文 README 的下载链接及相关说明。
3. 运行检查和独立配置验证，再运行 `npm run release`。
4. 检查 Git 变更，提交源码、文档及当前 `downloads/` 安装包。`node_modules/`、`build/` 和 `dist/` 已忽略。
5. 推送到 GitHub；如创建 Release，使用对应版本标签 `v1.0.1`，并上传 `dist/` 中的 XPI、源码 ZIP 和校验和。

本仓库没有自动上传、自动发布或自动更新服务。提交、推送及 GitHub Release 由维护者执行。

插件 ID 与偏好命名空间继续沿用既有值，覆盖安装无需数据迁移。不要因仓库目录改名而改动插件 ID、已保存的专用标签或用户列偏好。
